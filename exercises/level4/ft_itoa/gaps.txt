@@ intro
Two steps, because a malloc'ed string can't grow afterwards:

1. COUNT how many characters the result needs (the digits, plus '-' if negative),
   so you can malloc exactly the right size.
2. FILL the string from the END: `n % 10` gives the LAST digit of a number and
   `n / 10` removes it, so the digits come out right to left.

    ft_itoa(-1234):  len = 5
    [ - ][ 1 ][ 2 ][ 3 ][ 4 ][\0]
                          ^ the first digit found (4) is written here

One trap: INT_MIN. -2147483648 is a valid int, but +2147483648 is not (INT_MAX
is 2147483647), so turning it positive overflows. That's why the work is done on
a `long` copy of the number.
(long is 64 bits on the Linux exam machines; examshell adjusts that when grading on Windows.)

static int	count_len(long n)
{
	int	len;

	len = {{1}};
	while (n)
	{
		n /= 10;
		len++;

{
	long	n;
	int		len;
	char	*res;

	n = nbr;
	len = count_len(n);
	res = malloc({{2}});
	if (!res)

	res[len] = {{3}};
	if (n < 0)
	{
		res[0] = '-';
		n = {{4}};
	}
	if (n == 0)
		res[0] = '0';
	while (n)
	{
		res[{{5}}] = {{6}};
		n /= 10;
	}
	return (res);
}

In C a comparison IS a number: `(n <= 0)` is 1 when true and 0 when false.
So the count starts at 1 for zero and negatives, and at 0 otherwise:

- negative: 1 extra character for the '-' sign
- zero: `while (n)` never runs for 0, but "0" still needs 1 character

Then the loop adds one per digit, chopping digits off with `n /= 10` until
nothing is left: 1234 => 123 => 12 => 1 => 0 is 4 turns = 4 digits.

`len` counts the visible characters. Every C string needs one more byte for the
terminating '\0', so we allocate len + 1 bytes (indexes 0 to len).

`sizeof(char)` is always 1 by definition, so `malloc(len + 1)` and
`malloc(sizeof(char) * (len + 1))` are the same. Forgetting the + 1 is a classic:
the program often *seems* to work, then crashes somewhere else later.

Once the '-' is stored, we flip n to positive, so `n % 10` gives digits 0..9 (on a
negative number `%` gives negative remainders, like -1234 % 10 == -4).

This is exactly where INT_MIN breaks an int version: -(-2147483648) = 2147483648
doesn't fit in an int (max 2147483647). That overflow is undefined behaviour - in
practice n stays negative and you get garbage like "-./,),(-*,(". Since `n` is a
long (a bigger type), the positive value fits. Note that `-nbr` would NOT fix it:
it's computed in an int first, and only then stored in the long.

@@ gap 5
answer: --len
wrong: len-- => Postfix: it uses the OLD len first, so the first digit would overwrite the '\0' at index len.
wrong: len => len is the index of the '\0' - writing there destroys the terminator, and since len never changes, every digit lands in that same cell.
wrong: len - 1 => Right index for the first digit, but len never changes: every digit would be written into the same cell.
hint: len is currently the index of the '\0'. Move one step left BEFORE writing.
Prefix vs postfix, the key detail of this line:

- `--len` decrements FIRST, then gives the new value
- `len--` gives the OLD value, THEN decrements

len starts as the index of the '\0'. The last digit must go just before it, at
len - 1. With `--len` the first write lands on len - 1, the next on len - 2, and
so on. With `len--` the first digit would overwrite the '\0'.

Using `len` as a cursor that moves from right to left saves a second index variable.

hint: n % 10 is a number from 0 to 9. How do you turn the number 7 into the character '7'?
`n % 10` is the last digit as a NUMBER (0 to 9). A string holds CHARACTERS, whose
codes are different: '0' is 48, '1' is 49, ... '9' is 57. The digit characters are
consecutive, so:

    digit + '0'     =>     7 + 48 = 55 = '7'

Then `n /= 10` drops that digit, and the loop continues with the next one.

@@ outro
The digit pattern (you'll reuse it in putnbr, print_hex, atoi_base...):

    last digit:            n % 10
    remove last digit:     n / 10
    digit => character:    digit + '0'

ft_itoa checklist:
- count first, then malloc(len + 1), then put the '\0'
- 0 needs its own case: the digit loop never runs for it
- negative: store '-', then make n positive in a type big enough for INT_MIN
- write the digits from the end of the string towards the start
- return the malloc'ed string: freeing it is the caller's job
