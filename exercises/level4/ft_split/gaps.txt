@@ intro
ft_split returns an array of strings - a `char **` - that ends with a NULL pointer,
so the caller knows where it stops:

    ft_split("  hello \t world ")   =>   res[0] => "hello"
                                          res[1] => "world"
                                          res[2] =  NULL

Memory is allocated on two levels:
1. ONE array of pointers: (number of words + 1) slots, the extra one for NULL
2. ONE string per word: (its length + 1) bytes, the extra one for '\0'

So the plan: count the words => malloc the array => for each word: skip the
separators, measure the word, malloc it, copy it.

@@ file ft_split.c
#include <stdlib.h>

static int	is_sep(char c)
{
	return (c == ' ' || c == '\t' || c == '\n');
}

static int	count_words(char *str)
{
	int	count;
	int	i;

	count = 0;
	i = 0;
	while (str[i])
	{
		if (!is_sep(str[i]) && {{1}})
			count++;
		i++;
	}
	return (count);
}

char	**ft_split(char *str)
{
	char	**res;
	int		i;
	int		j;
	int		k;
	int		len;

	res = malloc(sizeof({{2}}) * (count_words(str) + 1));
	if (!res)
		return (NULL);
	i = 0;
	k = 0;
	while (str[i])
	{
		while (str[i] && is_sep(str[i]))
			i++;
		if (!str[i])
			break ;

		while (str[i + len] && {{3}})
			len++;

			return (NULL);

		while (j < len)

			j++;
		}

hint: Count the START of each word: a non-separator that is the very first character, or whose previous character is ... ?
We count word STARTS: a character that is not a separator AND is either the very
first character or comes right after a separator.

Two C details hide in there:

- Short-circuit: when i == 0, `||` stops before evaluating `str[i - 1]`, so we
  never read `str[-1]`. That's why `i == 0` must be on the LEFT.
- The parentheses are required: `&&` binds tighter than `||`. Without them,
  `a && i == 0 || b` means `(a && i == 0) || b`, which counts every character
  that follows a separator - including other separators.

answer: char *

wrong: char => sizeof(char) is 1, but each slot holds a POINTER (8 bytes). The array would be 8 times too small.

hint: res is an array. What is the type of ONE element of that array?
`res` is a `char **`: a pointer to the first element of an array whose elements
are `char *` (one pointer per word). So each slot is `sizeof(char *)` bytes -
8 on a 64-bit machine.

`sizeof(char)` would give 1 byte per slot: 8 times too small. Filling it overflows
the buffer, which often crashes much later - one of the nastiest bugs to find.

Handy trick: `sizeof(*res)` means "the size of what res points to", and stays
correct even if you change the type later.

The `+ 1` makes room for the final NULL.

    res[k]         the k-th string (a char *)
    res[k][j]      the j-th character of that string (a char)

`str[i + j]` is character j of the word inside the original string.

hint: How does the caller know where the array ends?
The array stores no length, so its end is marked with a NULL pointer - just like
'\0' marks the end of a string. That's what "NULL-terminated array" means, and
why we allocated count + 1 slots.

Callers then loop with `while (res[i])`.

@@ outro
The shape of the solution:

    count words             =>  malloc(sizeof(char *) * (count + 1))
    for each word:
        skip separators
        measure it          =>  malloc(len + 1)
        copy it + '\0'
        move i past it
    res[k] = NULL

Common failures:
- `sizeof(char)` instead of `sizeof(char *)` for the array of pointers
- forgetting a `+ 1` (for the NULL or for the '\0')
- treating only ' ' as a separator - the subject also says tabs and newlines
- "" or "   " must return an array holding only NULL, not crash
